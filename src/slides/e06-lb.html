A waiting request has not even started, so it counts four times as much. The coordinator keeps these numbers fresh.

Source: A. Gordić, Inside vLLM (2025). Queue lengths are illustrative.

With four engines, someone must choose one for each new request. The rule is one line. Here are four engines. Ask the room: which gets the next request? Give them a moment to do the sum. Some will pick engine 3 because it has the fewest running.

Engine 2 wins with 13, ahead of engine 3 at 14, even though engine 3 has fewer running. A waiting request means that engine is out of room, so it is penalized heavily. This simple formula does useful work. Notice how much of a real distributed system comes down to a one-line heuristic. The DP coordinator process periodically sends the queue lengths to the API server.
