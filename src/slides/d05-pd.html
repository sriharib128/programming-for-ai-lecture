Source: A. Gordić, Inside vLLM (2025)

Remember the two phases. Prefill is limited by compute and comes in bursts. Decode is limited by memory bandwidth and is steady, and users notice any stall. Running both on one GPU means a burst of prefill can disturb decode.

So run them apart. N instances only do prefill and write the KV cache to a shared service. M instances read it and do the decoding. A piece of code called a connector moves the data. That interface is still changing, so treat this as the idea rather than a stable API.

It costs extra machinery, and pays off when you are serving at large scale. A one-sentence takeaway from these five features: chunked prefill and prefix caching change how prefill runs, guided and speculative decoding change how decode runs, and this one separates the two.
