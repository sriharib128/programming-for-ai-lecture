KV cache

The KV cache stops the repeated work

Without a cache

45 token computations for 6 new tokens

With a KV cache

10 token computations for the same 6 tokens
computed in this passread from the cache

The cost: the cache lives in GPU memory, and it grows with every token.

Attention needs a key and a value vector for every earlier token. Those depend only on earlier tokens, so they do not change once computed. On the left, a five-token prompt and six new tokens, with nothing saved. The passes read 5, then 6, up to 10 tokens: 45 in total.

So we save them. That saved data is the KV cache, for keys and values. Now the first pass computes the five prompt tokens, and every later pass computes only the single new token: 10 in total. Keep the last line in mind. The cache is large, it lives in GPU memory, and it grows while the request runs. Most of the next few slides are about this one piece of memory.
