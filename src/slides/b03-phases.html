Two phases

A request has two phases: prefill and decode

Prefill

A forward pass over every prompt token.

Limited bycompute

Decode

A forward pass over the newest token only, using the cache.

Limited bymemory bandwidth

Decode computes one token, but all the model weights still have to be read from memory.

Source: A. Gordić, Inside vLLM (2025)

The cache splits every request into two phases, and they behave very differently. Prefill is the first pass, over every token in the prompt. It is mostly limited by how fast the GPU can compute. At the end we sample one token, so its length sets the time to first token, which is what a user feels before anything appears.

Decode is every pass after that: one new token, using the cache. You might expect this to be cheap, but the GPU still has to stream all the model weights out of its memory to compute that one token. So decode is limited by memory bandwidth. The gap between tokens is the inter-token latency. Two phases, two kinds of limit. That difference comes back several times.
