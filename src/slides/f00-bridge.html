From vLLM to our system

What vLLM handles, and what is left to you

vLLM handles

  • Picking requests on each pass
  • GPU memory
  • Batching
  • Using several GPUs
  • A web server

You still need to decide

  • Which prompt to send next, out of 100 million
  • Whether an answer is good enough to keep
  • What happens to a page when a node dies
  • Which model a page goes to next
  • How to use GPUs that come and go

vLLM answers one request very well. Nothing in it knows about your whole job.

That is the system experts built, and using it takes one command to start a server. It does much more than we showed, and if you are curious, the Inside vLLM walkthrough is the place to read about it. We could not have built this ourselves, and we did not need to.

But look at what happens when you have a real job to do. In our case, generating training data from a hundred million pages. vLLM does not know that. It sees one request at a time. Which prompt comes next, whether an answer is usable, what happens to a page when a node dies: none of that belongs in an engine. That is a second program, and you have to write it. It is also the program you are most likely to write yourself. That is Patram-Ingest.
