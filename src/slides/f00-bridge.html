Halfway

What vLLM handles, and what is left to you

vLLM handles

  • Scheduling requests on each pass
  • GPU memory for the KV cache
  • Batching and reuse of shared prompts
  • Spreading a model across GPUs
  • An HTTP server and load balancing

You still need to decide

  • Which prompt to send next, out of 100 million
  • Whether an answer is good enough to keep
  • What happens to a page when a node dies
  • Which model a page goes to next
  • How to use GPUs that come and go

vLLM answers one request very well. Nothing in it knows about your whole job.

Let us stop and take stock. That was the system experts built. It handles scheduling, memory, batching, multiple GPUs and serving, and you get all of it from one command. We could not have built this ourselves, and we did not need to.

But look at what happens when you actually have a job to do. In our case, generate training data from a hundred million pages. vLLM does not know that. It sees one request at a time. Which prompt comes next, whether an answer is usable, what happens to a page when a node dies, which model a page should go to next: none of that belongs in an inference engine, and rightly so. That is a second program, and you have to write it. This is the part you are most likely to do yourself in your career. It is also where the second half begins.
