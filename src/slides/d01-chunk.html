1 · Chunked prefill

A long prompt can hold up everyone else

Whole prompt in one pass

Pass 1long prompt P
Pass 2QR

Q and R wait a whole pass before they start.

Prompt split into chunks

Pass 1P: chunk xQ
Pass 2P: chunk yR
Pass 3P: chunk z

Q and R start early. P samples its first token only after chunk z.

# the whole change: cap the new tokens per pass num_new_tokens = min(num_new_tokens, long_prefill_token_threshold)
Source: A. Gordić, Inside vLLM (2025)

Problem: one very long prompt takes over an entire pass. Everyone else waits for it, and their time to first token gets worse.

Fix: split the prompt across several passes, and let others share each one. P takes three passes now, so its own first token comes a little later, and everyone else's comes earlier. You choose who waits. This is the same thing an operating system does with a time slice.

Look at how small the change is. If the new tokens exceed a threshold, cap them. The block indexing we already built takes care of the rest. In vLLM you enable it by setting long_prefill_token_threshold to a positive number. A good core design makes features small.
