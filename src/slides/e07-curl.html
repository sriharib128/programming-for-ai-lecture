Request lifecycle

One curl, from start to finish

curl -X POST http://localhost:8000/v1/completions -H "Content-Type: application/json" \ -d '{"model": "TinyLlama/TinyLlama-1.1B-Chat-v1.0", "prompt": "The capital of France is", "max_tokens": 50}'
Source: A. Gordić, Inside vLLM (2025)

Now all of it together, following one request. Press next to step through it. You send one curl command from your terminal.

It reaches FastAPI, served by Uvicorn, which handles the route on the event loop.

The prompt is tokenized and packed with sampling settings and a request ID. Then AsyncLLM takes over, on the same path as the offline engine.

Load balancing: the score from the last slide picks an engine, and the request is sent to that engine's socket.

The engine's input thread wakes up, decodes the message and puts it on the input queue.

The main thread picks it up and calls step repeatedly. Schedule, forward pass and postprocess: everything from Part 2, possibly with worker processes on many GPUs below it.

The output thread sends results back through its socket.

Two asyncio tasks in the API server receive them, and FastAPI returns the response to your terminal, with the finish reason and usage. A whole distributed machine, behind one curl. Any questions on this picture before we discuss how to measure it?
