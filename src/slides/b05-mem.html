The simple approach is what you would do for a tensor: one contiguous block per request. But we do not know how long an answer will be, so we must reserve room for the longest one it could be. Each request here reserves 16 slots. A has used 5 and B has used 6.

Request C arrives. It needs 16 slots in one piece, and only 8 remain. So C has to wait, even though most of the memory holds nothing. Memory now limits the batch size, and the batch size limits throughput.

This is not a small effect. The authors of vLLM profiled the existing systems and found that only about 20 to 38 percent of the cache memory held actual token states. The rest was wasted.
